# Theme V3 Phase 01：樱花猫咪回转寿司屋主题蓝图

## 世界观

主题发生在春日傍晚的日式小镇寿司屋：窗外是樱花枝、远处木屋与暖色街灯；室内以浅木柜台、暖白墙面、柔和红色灯笼和蒸笼香气构成温暖的店铺。数只拟人猫厨师在不同工位准备寿司，中央弧形回转带把料理从备餐区送到顾客面前。用户看到的应先是一间有纵深、有人在工作的店，再理解餐盘是可点选的商品。

画风为扁平卡通插画、矢量平涂和 Q 版角色；暖调马卡龙色、低对比远景、清晰但不过重的深棕线条、少量纸纹。物件形体柔软而准确，避免写实摄影、过度高光、霓虹边框和互不统一的素材拼贴。

## 3840×1080 空间规划

设计文件、母背景及主要定位稿统一以 **3840×1080、32:9** 为标准母版。不得用 16:9 源图强行拉伸；次级设备尺寸只能由母版同比缩放或针对实际屏幕重新排版。

| 母版坐标 | 分区 | 构图与使用要求 |
| --- | --- | --- |
| `y=0–170` | 顶部品牌/进度/助手信息带 | 保留上方低细节或浅色区域；灯笼和梁柱集中外侧或顶部边缘，不遮挡 DOM 文字。进度条继续由组件覆盖。 |
| `y=170–800` | 场景与主要互动舞台 | 两侧货架、食材罐和餐具形成中景；远端墙面与窗户展示樱花小镇。中央弧形传送带横贯约 `x=280–3560`，曲线轻柔且可理解为单一循环路线。猫厨师分布在操作台后侧，保留可读商品名/价格空间。 |
| `y=800–1080` | 前景服务区与现有功能控件 | 中央独立点餐台建议约 `x=1450–2390`，以 DOM 的中控按钮为可交互层；左右 `x=80–1400`、`x=2440–3760` 留给双侧购物车。服务台主体可以覆盖背景前景，但不遮挡按钮、数量和下单区。 |
| `x=0–280` 与 `x=3560–3840` | 边缘货架/建筑收口 | 左侧偏备餐食材和蒸笼，右侧偏碗碟、调味料或窗侧花枝；复杂细节降对比，避免与中间餐盘竞争。 |

上述是构图起点，需使用实际浏览器 DOM bounding boxes 校准。现有主页面固定顶部与底部区域约 196px、213px，中央是实际动态舞台；主题母背景要为这些覆盖区保留安静空间，后续再决定装饰台面的精确遮挡线。

## 画面图层与资产边界

1. **母背景层**：完整店内空间、墙面/窗景、樱花与小镇、货架和固定照明；固定的架构、灯笼灯罩和静态蒸笼可入图。无菜名、价格、说明字、二维码、交互状态或运动主体。
2. **回转餐台层**：独立餐台主体插画（背部/弧形轨道、近侧台沿可拆成后景与前景遮挡段），路线方向清楚、平面连续。不能用 CSS 圆角边框加阴影假装复杂机械台。
3. **猫咪角色层**：每个工位的角色插画独立于母背景。做动作动画的猫应进一步拆身体/手臂或前爪/刀具或餐盘/头部/蒸汽等层，先锁定锚点和前后遮挡，再制作可循环帧或可驱动部件。
4. **餐盘按钮层**：餐盘基底和接触阴影为可复用插画资产；商品照片、真实菜名、价格、推荐与售罄状态仍由现有 DOM 呈现。每张盘的点击热区必须和视觉盘对齐，并保留键盘 focus/Enter。
5. **点餐台层**：独立服务台图作为中下部视觉主体，可分背板、台面、近景挡板；现有 `CenterFunctionPanel` 的菜单/导航/历史/设置/呼叫按钮作为 DOM 按钮覆盖，触控面积和事件不变。
6. **环境动效层**：少量樱花瓣、蒸汽、灯笼暖光呼吸、炒锅火苗/火星等透明素材或轻量 Canvas/CSS 效果。只做辅助氛围，不覆盖文字和点击区域。运动可暂停，遵循 reduced-motion。
7. **功能外壳层**：顶部进度条、左右购物车、提示覆盖、主题转场分别有成组主题资产，材质与店内木、纸、陶瓷、布灯笼一致。

只交付一张场景背景会把猫、餐台、盘子、服务台一并烘焙在不可点击的静态画面里，也无法驱动切菜/端菜/炒菜循环、重排层级或在商品上显示实时数据。拆开主体能分别动画、复用、定位、遮挡和做交互热区；母背景保持低频静态，既容易维护也避免多份画面重复资产。

## 猫厨师角色分工建议

| 角色 | 固定工位 | 可循环动作资产建议 | 道具/状态 |
| --- | --- | --- | --- |
| 切菜猫 | 左侧备料台 | 前爪抬起/落下切菜，头部轻点；刀具与砧板单独层，刀刃高光短促 | 胡萝卜/黄瓜/鱼料小块，动作幅度受控，不做真实伤害表现 |
| 摆盘猫 | 中央后侧寿司台 | 取料、压饭团、摆放一份寿司；手臂/寿司/盘子分层 | 瓷碟、饭团、海苔；循环首尾姿态一致 |
| 端菜猫 | 传送带出口或右侧 | 双爪托盘、步伐/身体轻摆、将盘放上传送带 | 托盘以独立组移动，动作完成后盘进入既有流的逻辑节点 |
| 炒菜猫 | 左后侧小灶 | 锅铲翻炒、锅身轻摆、短促火苗/蒸汽 | 锅和猫身体分层；火焰独立透明素材，避免大面积遮挡 |

优先把角色设计成统一头身比例、轮廓线、光向、眼睛比例和围裙/头巾规则。角色动作不绑定具体菜单数据；动画失败/暂停时退化为静态姿势。

## 左→右传送带的物理叙事

- 采用“左侧备料/摆盘区 → 中央出品/检查点 → 右侧顾客侧”的单向视觉路径；角色动线、商品上带位置、导轨/台沿高光和指示物方向都一致，直观看懂菜品从厨房出发向右送达。
- 传送带在画面中央做宽弧形，但 DOM 商品继续沿现有单一水平循环滚动流；弧形用静态插画建立空间，不能另建第二套轨道运动和商品数据。
- 默认演示方向规划为左到右；设置中已有反向选项，接入时保留它。视觉箭头/进出点可随方向切换，盘面文字不做镜像，特殊事件和轻动效必须用同一方向参数。
- 所谓循环是商品从右侧出画后在左侧重新进入的界面循环，并由备餐/端菜循环动画补足“补货”语义。避免视觉上让食物沿一个闭环瞬间穿墙回到起点。
- 可点击餐盘在滚动时保持足够间距和按钮 focus；点选继续根据屏幕左右半区进入现有左右购物车，不让角色点击拦截商品点击。

## 下侧点餐台定位

将独立服务台放在 `x≈1450–2390, y≈820–1080`，画面下侧中央，正面略朝观众。上层台面允许与传送带近景台沿产生合理遮挡，但不可挡住菜单、导航、历史、设置、呼叫按钮的 DOM 点击区域。购物车分居两侧，形成“左购物篮—中央服务台—右购物篮”的功能关系。

服务台需要资产化为可拆背板/前沿/顶面，不直接画上静态菜单文字或按钮符号。实际边界要在 3840×1080 和 1920×1080 下验证；移动/窄屏时由现有响应式功能区域保证可用，不把母版绘制坐标硬编码为所有视口 CSS。

## 美术规格

- **建议语义色**：樱花粉 `#E8A9B5`、浅樱 `#F5D6D8`、奶油米白 `#FFF2DB`、抹茶绿 `#A9C49A`、木色 `#B8794E`、朱红 `#C75A4A`、墨棕 `#543B35`、远景灰紫 `#A99AAE`。以最终母图为准再转成 CSS tokens。
- **线条**：圆润统一的深暖棕轮廓；主体线条清楚，远景线条更细更淡。避免每个资源描边粗细不同。
- **材质**：浅木纹用克制色块/少量纹理，餐盘是哑光陶瓷，灯笼为纸质散射光，帘布/围裙为柔软布面；纸纹很轻，不能造成噪点。
- **阴影/光照**：统一柔和暖顶光，角色和盘子使用一致落影方向；接触阴影小而软。避免高对比黑影、外发光和多重滤镜。
- **密度**：中央传送路线和 DOM 交互面上留干净区域；窗外与两侧货架提供场景识别，视觉权重低于盘中真实菜品和角色。
- **无文字图像原则**：母图及复杂资产不烘焙会变化/翻译的字、菜单、价格、品牌或状态标识。

## 阶段交付判定

Phase 01 只建立蓝图与资源边界，不接入运行流程。进入视觉资产阶段前，先产出构图草图/色彩稿并验证 3840×1080 布局遮挡；角色资产确定锚点、循环姿势和导出格式后才制作全套拆件。
