# Theme V3 Phase 02R：餐盘、弧线与底部布局修正报告

日期：2026-10-26
分支：`themev3`
范围：只改独立预览文件；正式展示组件和订单事件均未改动。

## 1. 修正结果

- 调试盘从 **166×104 px** 改为默认 **340×210 逻辑 px**；宽度可调 **300–380 px**，高度按 210/340 比例同步为 **185–235 px**。逻辑尺寸、button 热区、aria 标签、焦点外框与视觉节点使用同一 DOM 元素。
- 传送盘数量从 8 个减为 **6 个**，不缩小尺寸来维持数量。浏览器计算的拟合弧长为 **4512 px**，6 盘弧长间距为 **752 px**。即使最大宽 380 px 并计入最大深度缩放，盘间仍有约 364 px 的中心距余量。
- 餐盘切线角限制在 ±1.2°，主体保持近水平；沿路径深度比例在约 0.94–1.02 之间变化，DOM 点击热区随节点变换。
- 底部调试布局改为真实三栏：左四槽购物盘、中央双菜单按钮 + 2×2 功能区、右四槽购物盘。左右下单按钮分别贴近中央区域。所有标签由 DOM 输出，仅展示空槽占位，不包含商品/订单数据和业务事件。
- 新增 100% 逻辑像素局部视图、缩放按钮、目标区快捷定位和拖拽平移。全景、中央裁窗和 100% 局部只改变查看窗口与等比缩放，不改 3840×1080 场景坐标。

## 3. 底部布局与正式组件对照

实际阅读的结构：

- `CenterFunctionPanel.vue`：两个独立的纵向 `menu-btn`，左右各触发 `open-detail-menu(left/right)`；中间 `first-row` 和 `second-row` 各含两个功能按钮，分别承接导航、点餐记录、系统设置、呼叫店员事件。
- `CartPanel.vue`：每侧按 `items` 渲染四个圆槽；左侧下单按钮通过 `order: 1` 放在槽位组右边，右侧按钮 `order: 0` 放在槽位组左边。每槽另有商品图/名、数量、加减区。
- `ConveyorBeltDisplay.vue`：父级顺序为左购物盘、中央功能面板、右购物盘；两侧分别传入原有购物车状态和事件。
- `conveyor-belt.scss`：3840 实际展示在浏览器 DOM 中的三栏尺寸与用户给出的参考基本一致；下方展示 y 由 flex 对齐决定。

**1920×1080 实际业务布局另行核验：** 真实 `/display` DOM 在 CSS viewport 1920×1080 时，`.bottom-section` 宽约 1920.5；左盘 x≈-275.8、宽827，中央 x≈581.2、宽758，右盘 x≈1369.2、宽827，左右边各溢出画布约276 px。每侧四个 DOM 槽位仍存在，但完整落在可视区的只有 2/4；左右下单按钮及中央 2×2 结构仍存在。原样式源文件有 1920 以下响应式声明，但在本次浏览器实际 viewport 核验中相应媒体查询未生效，导致子项按基础宽度溢出。**这是正式 `/display` 当前已有布局问题；本阶段按“不改正式业务页面”的范围将其记为未解决项，没有擅自改业务组件。**

预览的“业务布局对照”显示 3840 实测三栏全景；预览在 1920 viewport 的全景模式会等比缩到约 49%，保持全画布和所有槽位可见。独立“1920 中央视图”是 x=960–2880 的中心裁窗，它会按定义截到左右购物盘外侧；它不等于 1920 宽的正式业务响应布局。真实业务响应结果以上述 `/display` DOM 实测为准。

## 4. 视图、间距与空间冲突检查

- **A 3840×1080 全景：** 逻辑尺寸固定为 3840×1080；浏览器可用高度不足时只等比缩小显示。底部完整三栏在画布内。
- **B 1920×1080 中央视图：** 保持母版 x=960–2880，比例不变，居中内容显示；左右购物盘外侧会被中心裁窗裁掉，这是裁窗定义本身。
- **C 1920×1080 实际业务参考：** 已在真实 `/display` DOM 测量；当前存在左右各约276 px 溢出，不能宣称现有生产页面下四槽都完整可见。
- **D 100% 餐盘局部：** 逻辑 340×210 px 在 100% 模式下按 1 CSS px/逻辑 px 显示；缩放到 110% 后 host 仍裁窗，场景按相同比例放大，拖动平移生效。
- 最大尺寸 380×235 的测试盘点击热区来自同一 button，缩放/焦点提示跟随；轨迹控制点与热区 DOM 可视化并行。
- 盘体范围不接近顶部 y=0–196 信息带或底部 y=865 点餐区。盘体高度增加后会压在参考图原有固定寿司像素之上；原图猫和手部也被烘焙在图内，部分低位手势区域无法在这张合成图上做可靠遮挡判断。

## 5. 实测行为

- 浏览器 DOM 核验：默认 `340×210`、六个盘；宽度调至 380 后输出 `380×235`，button 的内联宽高和 aria 标签同步更新。
- 点击第三个测试盘后，状态区显示“已点中移动测试盘 3”，点击目标与移动 DOM 节点一致。
- 局部模式输出 100%；放大按钮变 110%；拖拽后画布 left/top 都改变；快捷聚焦餐盘、弧线和点餐台。
- 控制点 11 个（9 个图像点 + 两个画外端点），弧长 4512 px，六盘间距 752 px。
- 真实可视截图已通过浏览器现场查看：中心轨迹上的测试盘比旧尺寸明显变大；底部三栏显示左右四槽、中央双菜单和 2×2 功能区。截图工具未提供写入 `.visual-review/themev3/phase02r/` 的本地文件能力；页面截图在会话工具输出中查看，目录中没有伪造或占位截图。
- **运动周期的前后台测量限制：** 代码仍按 `speed × delta` 推进并对每帧 delta 限制 100ms。由于自动化浏览器标签处于后台时 Chrome 将 rAF 降至约 1 Hz，本次 360 px/s 长周期观察实际只前进约 324 px/10s，不能把后台采样当作真实前台速度或“出界后重入”的验收结论。路径端点距画布足以容纳最大盘宽，算法只在这两个画外端点取模；但前台完整周期需要在可见标签下补一次实测。
- 预览仍显示用户原图中的固定寿司。它们用于对照，不是运动对象；正式母背景必须移除这些固定餐盘并独立制作餐台前/后景，否则静态盘和动态盘会叠在一起。
- 当前路径根据原图已有盘心估测。由于猫、手臂、桌边和寿司都合并在单张参考图中，放大盘体后部分猫手遮挡无法精确判断；真实猫/餐台分层资产完成后必须重新校准带面接触线、猫手层级与餐盘遮挡。

## 6. 正式资产依赖与本阶段边界

仍需独立绘制：无固定寿司的母背景、回转带面与前缘/后缘、每款可点击正式餐盘、中央点餐台及台面/背板/前沿、左右购物盘外壳、四只猫的透明角色与动作拆件。菜单、购物车、进度、弹窗和按钮事件继续由现有业务 DOM/组件承载。本轮只改 `public/themev3-preview/` 的静态调试页和 Phase 02R 报告，没有改 `src/` 里的正式组件或订单逻辑。
