# Theme V4 · 第一步：两场景共用构图

配套构图稿：[查看 SVG](./01-common-composition.svg)。本稿只确定信息层级和美术可用范围，不是最终场景图，也未接入 `/display`。

## 设计决定

- 两场景暂定为「樱花寿司屋」与「海边寿司屋」。共用送餐路线、三只猫的工位、顶部信息区与底部功能区；靠少量远景元素区分主题。
- 母版为 3840×1080。顶部 `y=0–196` 留给品牌、进度、助手；底部 `y=865–1080` 留给左右购物区和中央功能区。数值来自当前正式页面样式及 V3 的 3840 浏览器测量。
- 中部 `x=390–3450, y=365–780` 暂定为**送餐净空区**。美术不在这里叠加猫身、花枝、海浪、招牌或前景遮挡；这里由送餐台、移动菜品、菜名、价格与必要控件占据。净空区外仍须保留舞台工具栏的可读空间。
- 场景识别带优先使用 `y=214–358` 的远景，以及画面两端的低对比装饰区。每场景主要识别元素最多三种；不通过增加物件数量补救主题识别度。
- 三个猫咪圆点只表示左、中、右三个固定工位。实际身体尺寸、接触线与前后遮挡必须在两张静帧中验证；不沿用 V3 未通过验收的猫图或背景作为正式资产。

## 第二步静帧需要证明什么

1. 缩小到正常观看尺寸，遮住文字后仍能在一眼内区分樱花与海边。
2. 菜品、名称、价格、台面轮廓和底部按钮始终清楚；没有前景主体压进净空区。
3. 三只猫在相同位置分别适配两个场景，脚/爪与工位的接触可信。
4. 分别按 3840×1080 与实际 1920×1080 页面查看。V3 记录的 1920 宽两侧购物区溢出属于现有布局问题，不能用“3840 母版中间裁切”冒充实际响应布局验收。

## 依据与边界

- 页面分区与主题流程：`src/views/display/ConveyorBeltDisplay.vue`、`src/styles/conveyor-belt.scss`。
- 3840 底部 DOM 测量及 1920 溢出记录：`docs/theme-sakura-cat-sushi-v3/PHASE_02R_CORRECTION_REPORT.md`。
- 净空矩形和猫工位是本轮**设计候选值**，尚未在当前浏览器 DOM 中复测。正式素材绘制前，应以实际餐盘及文字边界加安全间距校准。
