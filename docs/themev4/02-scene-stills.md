# Theme V4 · 第二步：两张场景静帧

两张静帧使用同一套 3840×1080 坐标和页面骨架，仅调整场景色彩与少量主题元素：

| 场景 | 静帧 | 一眼识别元素 |
| --- | --- | --- |
| 樱花寿司屋 | [SVG](./02-sakura-still.svg) · [预览 PNG](./02-sakura-preview.png) | 樱花枝、木质屋檐、暖灯笼 |
| 海边寿司屋 | [SVG](./02-coast-still.svg) · [预览 PNG](./02-coast-preview.png) | 海平线、两端遮阳棚、少量海浪 |

## 共用的位置

- 三只猫的头部中心：`x=560 / 1920 / 3280`；身体在送餐台后，由台面遮挡。这是工位构图候选值，并非最终角色资产锚点。
- 送餐台占中部主视觉，盘面和菜名/价格位于台面上。场景枝叶、浪花、灯笼和遮阳棚均在送餐区域之外。
- 四张示意菜品卡只用于判断商品可读性。名称、价格和按钮在正式实现中仍由真实 DOM 与数据输出，不应烘焙进背景图。
- 顶部品牌/进度/助手和底部购物/功能区的位置完全相同，便于逐项比较场景变化。

## 本轮视觉检查

- 两张图均已由浏览器从 SVG 渲染为 1920×540 预览；主题在该缩小尺寸下可区分。
- 猫咪位于台后，画面只露出头部，不遮盖菜品和台面。
- 菜品卡、名称与价格清楚；背景主题元素没有覆盖送餐台。
- 仍是**构图静帧**：菜品示意图、猫咪与操作区只是占位设计，不代表最终插画或可交互页面；未在真实 `/display` 的 1920×1080 响应布局中验收。

## 下一步所需校准

正式美术资产和转场动画开始前，应在真实 `/display` 页记录餐盘、文字和舞台工具栏的可视边界，特别检查 1920×1080 下已记录的两侧购物区溢出。通过后再把两场景拆成共享台面与各自远景图层。

本轮源文件由 `render_scene_stills.py` 生成，可重复输出两张相同骨架的 SVG。
