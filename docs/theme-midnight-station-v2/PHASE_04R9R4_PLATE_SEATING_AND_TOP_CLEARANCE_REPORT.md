## 问题诊断

R9R3 将重点放在进度条净空。由于它没有改动菜品锚点，红盘仍按 `cargoDeckTopRatio = 0.38` 对齐；红盘落在车厢上沿附近，视觉上仍像架在车厢上。该轮也把 `.tide-stage` 的裁切边界 `y=196` 当成饮料的自然顶边，没有计入源图顶部已被裁掉的部分。因此页面看起来没有修正餐盘姿态，饮料上沿也仍显得紧。

本轮测得 3840 下霸气橙子图片框顶部为 `y=143.0`，源图 alpha 顶部约 `y=166.7`，舞台裁切线为 `y=196`，约 `29.3px` 的有效图像顶部被裁掉。1920 下图片内容顶边为 `y=236.7`，高于舞台上沿 `y=178`，原本没有裁切。

## 餐盘与牌匾调整

- 在 `MidnightDishTrolley.vue` 增加单一的 `--midnight-food-seat-depth: 17%`。商品图框、资源、红盘大小均未改变；在现有 alpha 锚点上将整张商品图向车厢内下沉 17% 车身高度。前侧车身继续使用既有遮挡层，使红盘下缘进入车厢前沿之后。
- 3840 下商品图片框从 `y=143.0` 移至 `y=172.8`，下移 `29.8px`；图片框仍为 `441.9×441.9px`。红盘和食物的实际下缘从约 `y=566.8` 移至 `y=596.6`。
- 1920 下图片框从 `y=217.1` 移至 `y=241.7`，下移 `24.6px`；图片框仍为 `365.4×365.4px`。实际下缘从约 `y=567.5` 移至 `y=592.1`。
- 牌匾上沿从车身高度的 `38%` 调至 `44%`，高度从 `56%` 收至 `46%`，上下 padding 从 `5px` 收至 `2px`，文字间距从 `3px` 收至 `1px`。铭牌仍连接在车厢侧板，字号与宽度不变。

| 视口 | 牌匾位置（修改前） | 牌匾位置（修改后） | 修改后实际字号（名称 / 价格） |
| --- | --- | --- | --- |
| 3840×1080 | y=566.3–664.5，高 98.2px | y=576.8–657.5，高 80.7px | 31.872px / 34.56px |
| 1920×1080 | y=567.1–648.3，高 81.2px | y=575.8–642.5，高 66.7px | 26px / 27px |

按车轮未旋转的圆形几何计算，修改后牌匾底边高于车轮圆周最低点约 `21.5px`（3840）与 `17.8px`（1920）；牌匾上下留白减少，菜名字号和价格字号保持原值。移动端保留原来的牌匾和商品锚点，以免小屏空间被桌面落座深度挤压。

## 页面几何与商品抽样

背景铁轨、普通车体、车轮坐标、特殊列车、主舞台、分类栏和底部购物区均未调整。3840 下车体框仍为 `526.1×175.4px`，1920 下为 `435×145px`；车轮中心线保持在车体框顶边以下 76% 的位置。分类栏、购物框与修改前坐标一致。

真实浏览器中检查饮料、蛋糕、吐司、寿司布局探针和熟食主菜。各类商品保持同一图片框尺寸，按现有 `contain` 显示，没有新增缩放或裁切规则。连续商品局部图中车轮、车厢侧板和铭牌均完整可见；普通车与特殊机车同框时仍沿同一轨道运行。

本机 `127.0.0.1:48081` 商品 API 未运行。截图通过单个无头 Chrome 页面拦截两条菜单请求，使用 R9 图片清单商品数据与仓库本地图片渲染真实页面。该清单没有寿司商品；寿司局部图使用仓库现有的 `src/assets/games/sushi/sushi-normal.webp` 作为临时布局探针，未修改图片映射或正式商品资源。完整线上菜单仍需在用户页面复核。
