## R9 的问题与修复方式

R9 的图片框仍受旧版固定宽高约束。1920 下方形商品图被较矮的框限制，3840 下图片也被固定高度压缩。不同透明素材自身留白程度不一，而所有图片共用同一个固定 `bottom: 58%`，导致红盘与车厢承载台的视觉接触位置不一致。

R9R 将图片框改为随运输车宽度变化的方形承载区，最大宽度受限，不再依赖旧 `--midnight-food-width/height`。依据现有 WebP 的 alpha 可见边界，为每张图记录可见底缘比例；结合车身 3:1 比例、承载台位置和图片框宽度，计算各商品的底部锚点。无效图片切换默认 SVG 时同时更新图片框比例和锚点。

| 视口 / 项目 | R9 | R9R 浏览器实测 |
|---|---:|---:|
| 3840 商品图片显示框 | 约 221×221px（实际食物/盘面约 195–212px） | 442×442px（实际红盘约 389–424px） |
| 1920 商品图片显示框 | 约 175×175px（受旧框高度限制） | 365×365px（实际红盘约 321–350px） |
| 3840 车体 | 约 526×175px | 526×175px，保持不变 |
| 1920 车体 | 约 435×145px | 435×145px，保持不变 |
| 铭牌实际计算字号 | 保持 R9 规则 | 3840：名称 31.872px、价格 34.56px；1920：名称 26px、价格 27px |

主图框宽度分别为车体宽度的 84%，食物仍以 `object-fit: contain` 展示，不放大裁掉主体。透明边缘通过实测锚点参与定位，不再对所有商品统一套用放大变换。

## 真实浏览器验收

通过一个无头 Chrome 会话打开本地实际页面，CSS viewport 分别为 3840×1080 和 1920×1080，设备像素比为 1。实测数据：

- **3840×1080：**运输车身约 526×175px、商品框 442×442px、铭牌名称/价格 31.872/34.56px；全景中约 6 辆普通商品车同时可见，车轮和车身保持可辨。
- **1920×1080：**车身约 435×145px、商品框 365×365px、铭牌名称/价格 26/27px；4 辆车与视口相交，中央商品完整展示，左右边缘车随横向视口自然裁切。
- **连续商品：**全景和品类截图覆盖饮料、土豆炒肉、小蛋糕、橙饮、吐司等；商品大小提高后，相邻单元仍保持间距，未见铭牌互撞。
- **特殊列车同框：**单独截图包含普通运输车与特殊机车；滚轮仍接触轨道，特殊列车比例未被本次 CSS 修改。
- **默认回退：**以 `33333` 缺图商品捕获，默认插画清楚可见，车厢、铭牌与轮组仍完整。
- **底部界面：**两种全景均包含分类条和四槽购物区；本次未修改底部组件或共享几何。
